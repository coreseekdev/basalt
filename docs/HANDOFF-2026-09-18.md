## 2. 陷阱（本轮增量，接 09-17 handoff §2；51/52 详见账本）

1. **MetaCmd::Lookup 的 None/Some 二义**：`names: None` = 全量 topic；
   心跳 handler 恒传 `Some(...)`。
2. **KIP-848 keepalive 语义**：未变字段置 null——订阅 null ≠ 退订
   （tri-state 穿透组状态机）。
3. **nullable struct 线上原语**：int8 presence 标记（-1 null / 1 存在），
   与 flexible 无关（账本 51）——新增含 nullable struct 的 API 时布局
   探针不够，须真客户端过一遍。
4. **franz-go 848 的三道门**：ctx 键 `opt_in_kafka_next_gen_balancer_beta`
   + balancers[0] ∈ {sticky, range} + broker 宣告 68 max≥1。任何一门不
   满足 = 静默回退 classic 假绿。**错误码核对以 kerr/Errors.java 为权威**
   （UNSUPPORTED_ASSIGNOR=112 非 57，语义表双锁拦下）。
5. **TLA+ 审计位等式 RHS 必须加括号**：`x' = a \/ b` 解析为
   `(x' = a) \/ b`——名义 cfg 恒绿掩盖，只有突变体门禁才暴露。
6. **突变体捕获面要落准**：阴性对照的红必须是预期不变式的红。
7. **TLC 跨类型比较**：`#` 不做 string↔int 比较，占位符与成员同型。
8. **HeartbeatResult 是应答时刻快照**：多步组状态断言须读 actor 当前
   状态（cg.members[...]），且成员重入组前旧 epoch 心跳会被 fence——
   测试编排要模拟真实客户端的重同步节拍（uniform 多 topic 金样实测）。
9. **探针等待协调器回合必须先发齐全部请求再 await**：join→await→join
   的串行写法会撞 rebalance deadline（10s）被 27 冲刷——协作流的真实
   形态是「两请求在途、协调器凑齐即完成」。
10. **组协议/分配器选择面**：组协议 = leader 偏好序 ∩ 全体支持集；
    uniform 保留段按「topic 订阅者数升序」+ 补派订阅约束优先——两处
    都是防「唯一订阅 topic 饿死唯一订阅者」的同族约束。
